## 1. 核心观点（一句话）

作者用“完整流程”包装 AI 编程经验，主张从调研与需求规划开始，以小步任务、检查和记录提高做小工具的可控性。

## 2. 目标读者与使用场景

想用 AI 给自己做工具、但不知道从哪里开始或如何继续修改的新手。它提供流程心智模型，尚不能代替某个工具的安装、配置和端到端实操教程。

## 3. 内容展开路径

1. 封面给出时长经验与流程承诺；第 2 页先讲工具相似而使用方式不同，转入作者自述的开发经历。第 3 页展示修改崩坏、返工的落差，再以先写需求文档作为转折；经历和效率效果未独立核验。
2. 第 4–5 页强调从 GitHub 找工作流、提示词和经验，并以更新速度、星数增强说服力；没有核验这些质量判断。
3. 第 5–9 页把开发过程拆成要求、计划、验收条件、小任务、检查、存档、复盘和模板，使用实习生、施工图、任务卡等类比。
4. 第 10–11 页从日常操作习惯回到最小项目，劝读者实际跑通一次并保存有效流程，而非继续囤积教程。

## 4. 注意力钩子

- 类型：痛点直击与清单承诺。
- 原句：标题「不会vibe coding都给我去看啊啊啊！so easy」。
- 机制：直接点名不会做的人，承诺容易理解；封面的持续使用身份补可信感，但标题的轻松语气不证明技术门槛低。

## 5. 情绪曲线

- 开头：用强推荐语气和经验身份建立“我也能学会”的预期。
- 中段：把抽象开发任务拆成具体动作，增强可控制感；多页文字与术语也可能增加新手阅读负担。
- 结尾：把行动缩小到跑通一个项目，给出开始路径。是否能独立完成仍需真实测试。
