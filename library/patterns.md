# 规律库

每条规律一个 `### P-编号 名称` 小节，字段固定（`scripts/lint_library.py` 会校验）。

## 状态定义（只能按证据升降）

| 状态 | 条件 |
|---|---|
| 假设 | 1～2 个样本支持，或只来自单个账号 |
| 样本支持 | ≥3 个样本、来自 ≥2 个账号 |
| 自测有效 | 自己用过 ≥2 次，且这些帖子 d7 互动中位数高于自己全部帖子的中位数（`scripts/report.py` 算） |
| 自测无效 | 自己用过 ≥2 次，表现不高于中位数 |
| 废弃 | 用户决定不再用，写明原因 |

注意：自测样本少时（自己总帖数 <10）结论只能算参考，复盘时要说明基数。

## 字段

```
### P-001 规律名
- 类型: 标题|封面|开头|结构|结尾|选题|话题|发布时间
- 状态: 假设
- 描述: 一句话说清楚怎么做
- 模板: 用 [占位] 写的可套用句式
- 样本: S-xhs-xxx, S-xhs-yyy
- 自测: 2026-11-20-slug, ...（没有写 无）
- 备注: 适用边界、反例
```

### P-001 具体使用阻碍配一个可尝试动作
- 类型: 结构
- 状态: 假设
- 描述: 先说一个读者能识别的实际阻碍，再给一个可尝试的动作和验证边界，可能比只罗列工具能力更容易形成收藏与试用意图。
- 模板: 做[具体任务]总卡在[问题] → 我尝试[一个动作] → 用[实际结果]判断是否有用 → 保留[失败边界]

- 自测: 无
- 备注: report.py显示这三篇收藏/赞约1.31、1.23、1.30，只是计数结构，不能证明已使用或有效。UI帖有明确“没用”的反馈；GitHub需求改造可能比重写更复杂，许可证、部署与维护成本不能略过。没有自己的对照实验，不许承诺一句提示词解决问题或通过开源直接赚钱。教程补充样本收藏1395高于点赞1017，但主页赞数约2.79倍中位数未达3倍理想阈值，仅作同赛道收藏型对照；仍有带做、微调和规则兼容追问。未使用视频抽样支持本条。

### P-002 经历与身份认同需要成果和成本承接
- 类型: 标题
- 状态: 假设
- 描述: 持续投入或身份认同可让读者期待经验与鼓励，但必须用可核实的成果、失败与成本承接，单靠身份不证明能力。
- 模板: 在[可设定的故事场景]中推进[真实可复现的技术任务]，展示[实际技术成果]、[验证失败]和[真实成本边界]
- 样本: S-xhs-6adef93c000000000901b280, S-xhs-6ae0a523000000003501ebff, S-xhs-6a16d3b40000000008030b23
- 自测: 无
- 备注: 本条支持证据含两篇经验类及一篇工具链清单对照，保留假设。Elaine清单1条评论要求完整实测对比，说明素材整理不能代替成果证明；此为相关解释边界，不把清单强称经历帖。心得帖有1条读者要求展示长时间投入的成果，GitHub帖有改造复杂度反例。身份观点帖已归其他，其成本与个人品质批评仅是范围外的反例提醒，不计本条支持证据。故事角色、情节与场景可以设定；技术演示与产品数据必须真实，不能把星数、收藏或角色设定当能力证明。未使用视频抽样推断叙事或效果。

### P-003 评论追问指出用途与上手说明缺口
- 类型: 选题
- 状态: 假设
- 描述: 读者反复追问用途、工具身份、安装或获取方式时，可据其具体问题补说明，而不是继续增加功能清单。
- 模板: 读者问[具体问题] → 补[用途/身份/安装/入口之一] → 展示[实际步骤] → 说明[限制]
- 样本: S-xhs-6a0eed1f00000000070139e3, S-xhs-6a1ec58a0000000006037914, S-xhs-6ae9e718000000000e00f807, S-xhs-6adf3d8600000000170399c4, S-xhs-6a96ac89000000002901a77b
- 自测: 无
- 备注: Codex有5条安装/上手诉求，Cursor有2条通俗讲解诉求；视频软件帖有2条工具识别问题，硬件帖有用途2、硬件识别2、采购1、尺寸1、购买表达1。旧工具帖的13条入口请求来自同一篇，不是13个独立样本。视频两卡只提供已读评论证据，不支持完整视频结构、功能或实际效率。Cursor难懂、视频效率质疑均为反例；问题可能因只看标题或片段产生，不能断言作者完全没解释，更不能把追问、好奇或购买表达等同成交。评论已排除作者、机器人和广告，说明缺口仍需后续补充实验验证。
