# content-research：学别人怎么发帖，沉淀成有证据的规律

目标不是「收藏好帖子」，而是回答三个问题：**为什么它火、读者真正要什么、我能怎么用自己的素材复用**。

## 开始前必读

1. `AGENTS.md`（硬规则）
2. `positioning.md`（判断样本和我相不相关）
3. `library/patterns.md`（已有规律，避免重复建条）
4. 如果是分析某个账号：`library/accounts/` 下该账号的文件（有就更新，没有就新建）

## 输入来源（按可用性）

| 来源 | 怎么拿 | 注意 |
|---|---|---|
| 用户直接给 | 链接、截图、粘贴的正文和评论 | 截图要逐张读，评论截图同样要读 |
| 抓取工具 | Mac 上的小红书抓取 skill（如 autoclaw-cc/xiaohongshu-skills 的 explore）导出的 JSON | **只用小号；每批 ≤20 篇；不绕过限制**；字段缺失就标未知，不猜 |
| 其他平台 | X、公众号、知乎、B 站等同理，`platform` 写对应缩写（x / wechat / zhihu / bili） | 文件放 `library/samples/<platform>/` |

拿不到的数据（例如分享数、发布日期）填 `-1` / `unknown`，**绝不估一个数填进去**。

## 选样标准

只收**已被数据验证**的帖子：
- 互动明显高于该账号平时水平（同账号中位数的 3 倍以上最理想），或互动/粉丝比高
- 和 `positioning.md` 的受众或支柱相关；不相关但结构极好的可以收，`pillar` 填「其他」
- 同一个账号一批最多 5 篇，避免规律被单个账号带偏

## 流程

### A. 单篇拆解（最常用）

1. 复制 `templates/sample.md` 到 `library/samples/<platform>/<笔记id>.md`，id = `S-<platform>-<笔记id>`
2. 填 frontmatter：**url 和作者必须保留**，指标照实填
3. 按模板 1～9 节逐项拆解。规则：
   - 不改写、不润色、不夸赞；只描述结构和传播机制
   - 钩子必须给「类型 + 原句」
   - 第 7 节模板用 `[占位]` 写，不能带原文的具体内容
   - 原文只摘标题和关键单句，不整段复制
   - 信息不足写「未知」
4. **评论是重点**：按热度看前 20～50 条，记下读者「想要什么 / 卡在哪 / 问了什么」，同步到 `library/demand.md`（同类合并、次数 +1、补出处）
5. 第 9 节必须落到「我有什么真实素材能套这个结构」，没有就写没有

### B. 账号分析

1. 至少已有该账号 3 篇样本（不够先做 A）；<5 篇时 DNA 标「初步」
2. 复制 `templates/account.md` 到 `library/accounts/<id>.md`
3. 每个维度的「观察」都要指向例证样本 id
4. 必做一项对比：该账号互动最高的 3 篇 vs 中位数附近的 3 篇，差别在哪
5. 写「不适合我学的地方」

### C. 提炼规律（每积累约 10 篇新样本做一次）

1. 跑 `python3 scripts/report.py --samples` 看样本排行，数字以脚本输出为准
2. 在新样本里找重复出现的做法（标题、封面、开头、结构、结尾、选题）
3. 已有规律：把新样本 id 追加到「样本」，满足条件时升级状态（见 patterns.md 状态表）
4. 新规律：按 patterns.md 的字段格式追加，编号顺延，状态从「假设」开始
5. 发现反例（用了这个做法但数据差）写进「备注」，不要只收集支持证据

### D. 热点追踪（用户问「最近什么火」）

- 只报告**有数据支撑**的近期高互动帖子，每条带链接和互动数
- 说清楚是哪个时间窗口、看了多少篇；样本少就直说
- 给出和我定位相关的切入角度时，标明是建议，不是结论

## 收尾

1. `python3 scripts/lint_library.py` 无 ERROR
2. 向用户汇报：本次新增/更新了哪些样本、账号、规律、需求（列 id），以及**一条最值得用的发现**
3. 用户同意后 `git add`/`commit`/`push`（commit 信息写清新增了什么）

## 不做

- 不批量高频抓取、不用主号抓取、不绕过登录或验证码
- 不把样本原文整篇存进仓库
- 不在证据不足时把「假设」写成定论
