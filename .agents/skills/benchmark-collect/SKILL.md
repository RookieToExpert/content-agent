# benchmark-collect：对标原帖完整归档 SOP

本 Skill 用于将小红书等平台的垂直对标帖子**原汁原味搬运归档**到 `benchmarks/`，供人和 AI 写稿时直接看着原帖模仿创作。

## 核心原则（所有 Agent 必守）

1. **帖子文件只存「100% 原始帖子内容」，绝不掺杂 AI 分析！**
   - 单篇帖子 Markdown 里**只放**：基础互动数据、原帖正文原文、每一页的原图 + 图上原始文字（或视频分镜截图 + 原版口播逐字稿）、评论区原始评论。
   - **禁止**用 AI 的概括（如“第 2 页讲了用户痛点”）代替原图上的真实文字！**禁止**在单篇帖子文件里写长篇分析、结构拆解或免责声明。
2. **禁止使用乱码 ID 做文件名！**
   - 博主目录：`benchmarks/<博主名>_<粉丝数>粉/`（例：`benchmarks/林熙乐_350粉/`）
   - 帖子文件：`<序号>_<赞数>赞_<原帖标题>.md`（例：`01_1794赞_个人认为github搞钱最快的方式.md`）
3. **必须存齐每一页原图（`p01.png`～`pNN.png`）！**
   - 绝不能只存封面图。图文帖的每一页轮播图都必须保存到 `benchmarks/<博主目录>/assets/<序号>/p01.png`、`p02.png` … `pNN.png`。

---

## 本地浏览器抓取 4 步 SOP（给 Codex 执行）

### 第 1 步：采集博主主页（`benchmarks/<博主名>_<粉丝数>粉/README.md`）

1. 截取主页头部信息（昵称、简介、粉丝、获赞与收藏），存为 `assets/profile.png`。
2. 客观列出主页可见笔记列表（标题、原链、赞数、是否已归档原帖）。

### 第 2 步：进入单篇帖子，保存全部图片与原始文本

在浏览器打开目标帖子详情页，依次获取：
1. **互动数据裁片**：存为 `assets/<序号>/metrics.png`（含作者、赞、藏、评数字）。
2. **原帖正文区**：**一字不改**复制笔记标题、完整正文段落、底部全部 `#话题` 标签、页面显示的发布/编辑日期与地点。
3. **全部内页图片与图上原文**：
   - **图文帖**：点击轮播图从第 1 页翻到最后一页，将每一页原图保存为 `assets/<序号>/p01.png`、`p02.png` … `pNN.png`；同时**把每一页图片上的文字一字不漏地照抄下来**（保留原图的标题、正文、列表层级）。
   - **视频帖**：保存封面 `assets/<序号>/cover.png` 及关键画面截图 `s01.png`…，并将**视频完整口播台词/字幕一字不漏转录为逐字稿**。
4. **原始评论**：复制前 10～20 条真实读者评论的**原话**（跳过机器人总结和广告）。

### 第 3 步：按「纯原帖模板」写入文件

生成 `benchmarks/<博主目录>/<序号>_<赞数>赞_<原帖标题>.md`，格式固定如下（只放原始内容，不写分析）：

```markdown
# <原帖标题>

[⬅ 返回博主主页](./README.md) · [返回对标总览](../README.md) · [小红书原帖链接](<url>)

## 一、基础数据

- **作者**：<博主名>（<粉丝数> 粉）
- **数据**：<赞> 赞 · <藏> 藏 · <评> 评
- **时间**：<页面显示日期>
- **形式**：图文（共 N 页） / 视频（时长 X:XX）

![互动数据](assets/<序号>/metrics.png)

## 二、帖子正文与话题（原文）

<一字不改粘贴帖子正文>

<一字不改粘贴 #话题1 #话题2 ...>

## 三、全部内页原图与图上原文（共 N 页）

| 页码 | 原图 | 图上原始文字（逐字转录） |
|---|---|---|
| **P1** | <img src="assets/<序号>/p01.png" width="260" /> | <原图第1页上的全部文字> |
| **P2** | <img src="assets/<序号>/p02.png" width="260" /> | <原图第2页上的全部文字> |
...

## 四、评论区原始留言摘录

- **读者 A**：「<评论原话>」
  - **作者回复**：「<如有，贴原话>」
- **读者 B**：「<评论原话>」
```

### 第 4 步：在 `benchmarks/README.md` 登记一行分类索引

在 `benchmarks/README.md` 的总表里加一行（所属分类、卡片样式、链接），方便写新帖时直接按分类挑一篇原帖照着写。

## 执行前检查与可重复验收

以下检查补充上面的归档格式，不将缺页材料或摘要改称完整原帖，也不允许扩大本次任务范围。

### 先核身份、权限和会话
- 每轮先读取最新 `AGENTS.md`、本 Skill、`benchmarks/README.md` 及已有目标博主目录，确认本轮范围和是否有人并行写入。
- 昵称只作为搜索线索；用实际主页 URL／平台用户 ID，结合简介和内容交叉核对目标身份。遇同名、改名或身份不确定，先标待核实，不冒认账号。
- 老麦的工具库、秋芝 2046、数字生命卡兹克、歸藏／歸藏的AI工具箱是目标名称，不是已经核实的账号 ID；首次采集须分别核实。
- 遵循用户最新明确指定的环境；未另指定时沿用仓库默认的 Mac 本地浏览器。用户明确选择云电脑时使用其指定云会话，但不得自行切换以绕过限制。先核实实际登录状态。出现登录墙，保留登录入口并报告；不能以空搜索结果宣称博主不存在。
- 遇安全验证、访问频控或异常封禁提示立即停止本轮相关操作，不连续刷新、切换账号或环境绕过。不保存密码、验证码或认证会话信息。
- 完整复制第三方内容前，确认具备适用的归档权限并遵守版权限制。无法满足时报告阻碍，不擅自把本库改为摘要库，不用缺失或替代内容凑齐模板。

### 先去重，再逐篇采集
- 以主页的稳定身份和帖子稳定 ID 去重，不用昵称、赞数、标题或粉丝数单独判定唯一性。保持上面的可读文件命名，不改用 ID 作文件名。
- 先核对旧目录和原链；粉丝数或标题变化不能导致同一博主、同一帖子重复归档。确需重命名时同步检查引用，不覆盖已有不同帖子。
- 在本轮执行记录中逐篇记实际北京时间、帖子链接、页面显示页数、已保存页码，以及正文／评论／视频状态；沿用现有记录位置，不将工作流水账混入纯原帖文件。
- 未显示的数据记为未知，区分页面发布日期与采集时间；评论不足、折叠内容无法展开、某页未加载时如实记录，不能补造。

### 逐项验收后才算完成
- 逐张打开图片核对：页码连续、数量与页面显示一致、每张确为对应页且可读，无空白、截断、错误页或重复页。封面不能代替全部内页。
- 核对正文、图中文字和评论与可见来源相对应；识别不清的内容不猜写，缺失内容不以概括替代。视频字幕片段不能冒称完整逐字稿。
- 检查 Markdown 相对链接、图片路径和导航可用，标题与序号不冲突；检查截图及文本中是否含无关个人数据、认证信息或公司敏感内容。
- 读取并运行仓库当前适用的校验命令；不存在对应校验或环境无法运行时准确说明，不虚构 lint 通过。结构校验通过不代表素材完整或原文准确。

### 并发、提交与恢复
- 写入前核对最新远端及本地改动；只提交本批授权文件，保留其他工作，禁止强推覆盖并发提交。发生冲突先读新内容再合并，不盲目重复写入。
- 推送后回读远端文件、索引和资产，确认预期改动确已到达目标分支。结果不明时先查远端，不反复创建相同内容。
- 中断后从已核验的逐篇状态恢复；未核实成功的步骤不得直接当作成功，也不得不检查就重做。
- 向用户分别报告已确认账号数、已查看帖子数、完整归档数、部分或阻塞数及具体缺口。首次端到端采集未完成时，明确流程仍待实采验证；不得承诺今后绝不出错。
