# content-review：用自己的数据修正规律

一切结论以 `scripts/report.py` 的输出为准，不心算、不凭印象。

## 开始前必读

`AGENTS.md`、`library/patterns.md`、本周涉及的 `posts/*/post.md`

## A. 填数据

1. 数据来源：创作者中心截图、导出的 CSV（如 white0dew/XiaohongshuSkills 的笔记数据导出）、或用户口述
2. 时间点：发布后第 1、3、7 天各一次，写进对应 `d1_/d3_/d7_` 字段；拿不到的留空，**不估**
3. `leads`：本帖带来的私信咨询 + 口令使用次数（用户提供）
4. 截图要逐张读；数字读不清就问

## B. 评论处理

1. 读自己帖子的评论（用户截图或抓取导出）
2. 分类：产品咨询 / 功能建议 / Bug / 选题需求 / 课程意向 / 普通互动
3. 前四类写进 `library/demand.md`（合并同类、累加次数、出处写帖子 id）
4. 给每条需要回应的评论写回复草稿：具体、像人说话、不带外链和联系方式；Bug 先确认复现条件
5. 草稿只交给用户，**由用户确认后自己发**
6. Bug 和功能建议另外单独列给用户，方便转到产品仓库

## C. 周复盘（每周一次）

1. `python3 scripts/lint_library.py` 先通过
2. `python3 scripts/report.py --samples`，基于输出写复盘：
   - 本周发了什么，各帖 d7 表现（引用表格）
   - 表现最好和最差的各一篇：**对照它们用的规律和选题**说为什么，区分「数据支持的判断」和「猜测」
   - 规律状态：report 里标「⚠ 是」的，按状态表更新 patterns.md，并在规律「备注」写一行日期 + 依据
   - 需求池：本周新增了哪些需求，有没有出现次数明显上升的
   - 下周建议：2～3 个选题（引用需求 id 和规律 id），由用户定
3. 自己帖子总数 <10 时，每个结论都要注明基数小
4. 复盘写到 `reviews/<YYYY>-W<周数>.md`，用户确认后 commit/push

## D. 月复盘（每月一次，周复盘基础上加）

- 涨粉和线索主要来自哪个支柱、哪种角色、哪类选题（引流帖按浏览/涨粉评，干货帖按收藏评，不混在一起比）；`positioning.md` 的支柱比例要不要调（只建议，用户定）
- 哪些产品口令有转化；产品露出方式要不要改
- 课程信号：`demand.md` 里「课程意向」和高频选题需求的累计情况；够不够开始做课程调研
- 规律库清理：长期「假设」没有新证据的，建议降级或废弃

## 不做

- 不在数据不足时下结论，不把一次爆款当成规律
- 不替用户发送评论回复
- 不擅自改 `positioning.md`
